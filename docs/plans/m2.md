# M2 execution plan: single agent with tools

**Brief:** *Single agent with tools: mock order-lookup API, mock refund/replace API, shipping-tracker API, refund-amount calculator.*

**Status:** Done 2026-10-11 (P1–P4 as recommended). Results: [milestones/m2](../../milestones/m2/README.md). Alembic baseline delivered (step 3, LLD-3 L3a); migration drift test added.

## Decisions
| # | Decision |
|---|---|
| P1 | Local PostgreSQL in Docker for development and tests; Azure Database for PostgreSQL (B1ms, Entra auth) for the recorded demo |
| P2 | Own provider-agnostic tool-calling loop: `LLMClient.complete_with_tools`, implemented for OpenAI-compatible function calling; final answer submitted through a `submit_result` tool whose schema is the agent's output model |
| P3 | Customer identity passed by code in an `X-Customer-Id` header (never by the model); signed caller-context token arrives with the MCP server in M6 |
| P4 | Refund calculator: paid minus already refunded; shipping fee refundable only for damaged, defective, wrong or missing items; return-window eligibility arrives with the rules engine (M3–M4) |

## Steps
| # | Step | Output |
|---|---|---|
| 1 | Order Platform domain | Money, Order, OrderItem, Shipment, Refund, Replacement; refund quote and refund decision (cap ₹5,000 → pending approval); exceptions |
| 2 | Order Platform application | Ports (unit of work, repositories), use cases for the seven endpoints, idempotency |
| 3 | Order Platform adapters | SQLAlchemy 2.0 async models and repositories, Alembic migration, FastAPI routes with structured errors |
| 4 | Seed data | Faker `en_IN` generator + golden fixtures (C0001–C0010, ORD-100001…), anchored dates |
| 5 | ShopSense ports and adapters | `OrderTools` port, HTTP adapter (`X-Customer-Id`, `Idempotency-Key`), tool-calling support in the LLM gateway |
| 6 | Order-Actions agent | Tool loop (≤ 6 calls, 20 s), argument validation, deterministic idempotency keys, at most one write per run, structured `OrderActionsResult` |
| 7 | Evaluation | ~30 tool-use scenarios: right tool, right arguments, outcome; zero refunds above the cap executed |
| 8 | Infrastructure | `infra/local/compose.yml` (PostgreSQL), `infra/m2` Bicep (Azure PostgreSQL) |
| 9 | Milestone folder | `milestones/m2/` README, demo, `results/` |

## Acceptance
- ruff, mypy `--strict`, pytest pass (unit + integration).
- Tool-use suite: correct tool and arguments ≥ 85%; **zero refunds above ₹5,000 executed**; zero refunds above the amount paid.
- Demo: track an order, small refund executes, large refund held for approval, replacement created.

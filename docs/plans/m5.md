# M5 execution plan: LangGraph workflow with approval and checkpoints

**Brief:** *LangGraph workflow: triage → policy-check → action execution → conditional routing (auto-resolve low-risk, human-approval interrupt for high refunds or angry-customer sentiment), with checkpointing.*

**Status:** Done (2026-10-11). Results: [milestones/m5](../../milestones/m5/README.md).

## Decisions
| # | Decision | Why |
|---|---|---|
| W5-1 | The risk gate is code (`domain/workflow/risk.py`): REPLY, AUTO, APPROVAL, HUMAN | D10: the model never routes or writes |
| W5-2 | Writes only in `execute_auto` and `execute_approved`; `execute_auto` refuses any route but AUTO | "No write without passing the gate" is enforced and tested |
| W5-3 | The approval interrupt comes before any write; a rejected request writes nothing | A held refund must never be written first |
| W5-4 | LangGraph is an adapter over application steps (LLD-1) | Steps are testable without the framework |
| W5-5 | Postgres checkpoints (`AsyncPostgresSaver`, shopsense database, Entra token) | Paused tickets survive a restart (checkpoint round trip) |
| W5-6 | Reviewer decision endpoint on the Order Platform (`POST /v1/refunds/{refund_no}/decision`); settlement is simulated | Money invariants stay in the Order Platform; reviewer identity and signed grants come at M6 and M8 |
| W5-7 | Refund idempotency key = hash(ticket, SKU, amount, stage) | A retried step replays the same refund |

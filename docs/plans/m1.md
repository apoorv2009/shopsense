# M1 execution plan: ticket parsing

**Brief:** *Parse support tickets into a validated Pydantic SupportTicket object (issue type, order ID, sentiment, urgency) via a provider-agnostic client.*

**Status:** Approved scope (aligned with [D16](../adr/016-milestone-alignment.md)) · **Primary:** OpenAI `gpt-4.1-mini` on Foundry, East US 2 · **Second vendor:** Meta `Llama-3.3-70B-Instruct` on Foundry (JSON mode) · **Claude:** adapter built, disabled (no quota on trial, [D15](../adr/015-free-trial-profile.md))

## Steps
| # | Step | Layer | Output |
|---|---|---|---|
| 1 | Scaffolding | Repo | uv workspace, `services/shopsense_api`, `libs/contracts`, ruff, mypy `--strict`, pytest + coverage, structlog JSON, `.github/workflows/ci.yml` |
| 2 | Domain contracts | Domain | Frozen Pydantic `SupportTicket`; `UntrustedText`, `OrderId`, `Money`; enums `IssueType` (D14f), `Sentiment`, `Urgency`, `ProductCategory`, `RiskFlag`, `Language`; exceptions `DomainException`, `InvalidOrderId`, `TriageFailed`, `LLMUnavailable`, `LLMRefused` |
| 3 | Application contracts | Application | `LLMClient` port (agent profile, system prompt, trusted facts, untrusted blocks, output type), `PromptRepository` port |
| 4 | Use case | Application | `TriageTicket`: random-ID delimiters; one retry on validation failure with error feedback; second failure → `TriageFailed`; triage prompt v1 |
| 5 | Adapters | Adapters | Foundry Claude adapter (`AnthropicFoundry`, Entra auth, structured outputs, effort = low; refusal → `LLMRefused`, fail closed); Azure OpenAI adapter; LLM gateway (profiles, retries, provider fallback, token metering); regex injection screen |
| 6 | Composition | Entrypoints | `settings.py`, `composition.py` |
| 7 | Eval data | Evals | Golden 20 (triage fields); ~150 noisy tickets generated from Bitext intents with brief ratios; field-accuracy runner with flag recall |
| 8 | Milestone demo | `milestones/m1/` | README (brief, what was built, how to run, results); demo script: showcase tickets, same ticket on both providers, accuracy table |
| 9 | Infrastructure | Azure | Foundry project with Claude Opus 5.5 and Azure OpenAI deployments (Bicep) |

## Tests
| Level | Coverage |
|---|---|
| Unit (< 5 s) | Domain validators and invariants; delimiter wrapping; prompt rendering; use case with fake `LLMClient` (success, retry, refusal, second failure); gateway fallback with fake providers |

| Eval | Golden + triage suite, 3 runs |

## Acceptance
- `ruff check`, `ruff format --check`, `mypy --strict`, `pytest --cov` pass.
- Triage accuracy ≥ 85% on golden + triage suite.
- Injection, legal and safety flag recall 100%.
- Demo shows the same ticket parsed by both providers.
